## 2. Architecture
src/main.rs -> config.rs (TOML, 515 lines) -> engine/{app,core,player,render,world}.
- Main loop: winit 0.29 `about_to_wait` (app/runtime.rs:240-256): player update -> `update_world_streaming` (runtime.rs:437: `streamer.pump` then `renderer.pump_meshing`) -> `request_redraw` -> `Renderer::render` (renderer.rs:764). Everything world-related runs on the main thread each frame between redraws, with per-frame budgets. PresentMode::Fifo (renderer.rs:188).
- Threads: `ThreadedGenerator` (world/generation.rs) and `ThreadedMesher` (render/meshing.rs, note: meshing orchestration lives in render/, algorithm in world/mesher.rs) each own std::thread workers + crossbeam unbounded job/result channels. Worker counts: avail-1 split 1/3 gen, 2/3 mesh (runtime.rs:476). No rayon. Request-id + generation stamping discards stale results (generation.rs:117, meshing.rs accept_result). Separate async saver thread (persistence.rs:42).
- Data flow: StagedGenerator.generate (worker) -> Chunk -> channel -> main thread `World::insert_chunk` (storage.rs:~60; marks self + 6 neighbours dirty) -> `ThreadedMesher::enqueue_dirty` (main thread: takes dirty, sorts ALL deferred by priority each frame, captures snapshot = 7 Arc clones) -> worker meshes -> result -> main thread `upload_chunk_mesh` (render/renderer/mesh_upload.rs:12) -> `queue.write_buffer` per face-slice into one big MeshPool buffer -> `Renderer::render` CPU-culls and writes draw lists.
- Chunk lifecycle state machine Dirty->Queued->Meshing->Meshed->Uploaded keyed per generation (world/lifecycle.rs) — a second AHashMap per chunk; mostly stats/stale rejection.

## 3. Data structures
- CHUNK_SIZE = 32 (core/types.rs:3), volume 32768.
- Voxel = `u32` newtype (world/voxel.rs:5) holding a u16 BlockId: 128 KiB/chunk raw, 4x bloated vs u16 and 16x vs palette. No palette, no RLE, no empty-chunk shortcut (air chunks still allocate 128 KiB + 6 KiB tints). Measured: 676 generated chunks = 22.1M voxels, 38.7% air.
- Chunk = `Arc<[Voxel;32768]>` + `Arc<[ColumnBiomeTints;1024]>` (3+3 bytes per column x2, 6 KiB) + u32 generation (world/chunk.rs:41). Arc clone-on-write (Arc::make_mut) lets mesh snapshots share storage with zero copy; but an edit while a snapshot is alive copies 128 KiB. Good idea, keep (in some form).
- World = `AHashMap<ChunkCoord, Chunk>` (storage.rs:22) + dirty AHashMap + dirty Vec + lifecycle AHashMap + edit log. No ring buffer / flat array; every neighbour lookup (6 per snapshot) is a hash probe. Chunks are 3D (render_radius_y = 4 -> 9 vertical layers), default radius 12 x 4 => 25*25*9 = 5625 chunks.
- Persistence: ONLY a block-edit log (world pos -> BlockId) serialized as pretty TOML (persistence.rs:274), atomic write + backup rotation + corrupt archive, async debounced saver (125 ms). Chunks are never saved; world = seed + edit overlay, regenerated on load. Fine for a demo; O(edits) TOML will not scale.

## 4. Meshing
- Algorithm: per (face dir 6 x depth slice 32) build 32x32 mask of MaskCell {visible, block_id, texture_id, bucket, tint} then classic row/column greedy merge (world/mesher.rs:~230-330). Naive per-voxel `get_voxel` + ResolvedBlock lookups, `Instant::now()` pairs per slice for profiling (192 slices x 2 x Instant::now per chunk — measurable overhead). NOT binary greedy; no bitmask face culling.
- Output quad = `PackedFace {value:u32, tint:u32}` = 8 bytes/quad (gpu_types.rs:11-48): x5 y5 z5 tex7 w5 h5 in the first word; tint RGB + mode in the second. 8 B/quad is already compact (vs 24-36 B/vertex typical). Limitation: tex ids <=128, per-quad tint (grass colour) breaks greedy merges across biomes.
- NO ambient occlusion (grep: none in mesher/shaders). Only fixed face_shade (1.0/0.86/0.72) in fragment shader. No lighting at all, no sky/block light.
- Cross-chunk: snapshot of centre + 6 face neighbours; boundary slices read the neighbour's adjacent layer (mesher.rs prefetch_neighbor_slice). Missing neighbour => treated as AIR, so border faces toward unloaded chunks are emitted then mesh must be rebuilt when neighbours arrive (insert_chunk marks neighbours' border dirty -> double meshing during streaming). No edge/corner neighbours (not needed without AO).
- Incremental: ChunkMeshDirtyRegion = 6x u32 slice bitmasks (mesher.rs:24-130); edits re-mesh only the touched slices, with a per-chunk cached `ChunkMeshSlices` ([2 buckets][6 dirs][32 depths] of Vec<PackedFace> = 384 Vecs/chunk, kept in mesh_caches on the main thread => 384 heap vecs per resident chunk). Neat but allocation-heavy; flatten() re-concatenates and allocates 12 Vecs per result.
- Opaque/transparent split into 2 buckets (water, leaves) and 6 direction slices -> up to 12 GPU slices/draws per chunk.
- MEASURED (release, 1 thread, scratch bench using StagedGenerator + real biomes.toml, 12x4x12 area region, i.e. realistic terrain): generation 4.95 ms/chunk (3.35 s for 676 chunks); meshing+flatten 1.22 ms avg/chunk across 242 interior chunks (p50 1.31, p95 1.41, max 1.48; 164 non-empty, avg 268 greedy quads/chunk, 64.9k quads = 507 KB); chunk (0,0,0) in a hot loop 0.84 ms. Extrapolated to default 5625 chunks: ~28 s gen + ~7 s mesh single-threaded; on N threads divide. Meshing ~1 ms/chunk is 5-20x slower than a binary-greedy mesher (typically 50-200 us for 32^3/62^3). Even air-heavy chunks cost ~full 192 slice passes.
- Generator: per chunk it calls `sample_column` 1024x (2D fbm blueprint/climate/rivers/biome) plus 3D density fbm (4 octaves) on 32768 voxels. Column work is redone for each of the 9 vertical layers (no column cache). All scalar f32 Perlin, no SIMD, no early-out for chunks wholly above/below the surface.

## 5. Rendering
- wgpu 0.20 (stale; Lemon CLAUDE.md targets 30). Features requested: MULTI_DRAW_INDIRECT + INDIRECT_FIRST_INSTANCE if available, with a per-draw dynamic-offset fallback (renderer.rs:150-165, 659). Note multi_draw_indirect is native-only/not on Metal, and the fallback issues one draw + one set_bind_group per slice.
- Geometry: instanced quads. Static 4-vertex unit-quad VB, each instance = one face read from a STORAGE buffer `faces[draw_meta.face_offset + local_instance]` (shaders.wgsl vs_main). Vertex pulling in the VS; a trick `first_instance = draw_index * CHUNK_VOLUME` encodes the draw id in instance_index (gpu_types.rs `GpuDrawIndirect::for_draw`) with `/ % chunk_volume` per vertex. Limits: draw count capped at max_visible_draws=32768 (config.toml:21), and silently truncates + drops all transparent draws when exceeded (renderer.rs ~855). Quad-instancing with 4 verts/instance is poor GPU occupancy (tiny instances, 4-vertex draws with ~268 instances each).
- Buffers: one big face buffer `MeshPool` (render/mesh_pool.rs) with a first-fit sorted free list, linear scan (`position`) alloc and neighbour merging on free. When allocation fails -> `ensure_mesh_capacity` DOUBLES and repacks via copy_buffer_to_buffer, rebuilding the scene bind group (mesh_upload.rs:110-170), and `live_face_count()` iterates every gpu entry (O(chunks x 12)). Initial 4M faces = 32 MB (config initial_face_capacity). Fragmentation is handled only by this stop-the-world repack. Upload = `queue.write_buffer` per slice (up to 12 per chunk) on the main thread (mesh_upload.rs:49), budgeted 6 chunks/frame (mesh_upload_budget).
- Culling (CPU, every frame, renderer.rs:803-880): iterate ALL gpu_entries (AHashMap) -> frustum AABB test (frustum.rs) -> optional Hi-Z -> push up to 12 DrawMeta per chunk -> sort opaque by (x,y,z,dir) (pointless for GPU, sort cost O(n log n) per frame) -> transparent sort by distance back-to-front per chunk-direction -> insert into a HashSet (drawn_chunk_origins) just to count drawn chunks -> write_buffer draw_meta + indirect buffers (full re-upload each frame). No backface/face-direction culling per chunk (all 6 dirs drawn if chunk visible, even though ~half are back-facing; could cull per dir-slice by camera side). Scratch Vecs are reused (good) but the work is O(visible draws) CPU per frame, in the single render thread.
- Hi-Z (render/hiz.rs 819 lines + hiz.wgsl): a depth pyramid is built on GPU (render passes reducing depth), then read back to CPU through map_async into one of 3 slots (record/start_readback/update_readback with device.poll(Maintain::Poll) each frame, renderer.rs:~775), and `is_chunk_occluded` projects each chunk AABB and tests against the CPU copy of the pyramid, reusing the previous frame's camera when close (config max_camera_reuse_distance 8, forward_dot 0.97). I.e. CPU-side occlusion with 1-3 frame readback latency -> popping/ghosting risk, hence mitigations and "near_chunk_skip_distance 48". Disabled by default; there is no evidence in the history it was ever measured as a win. GPU-driven culling (compute -> indirect) was NOT implemented despite the CPU/GPU split being designed around DrawMeta/indirect buffers. Unit tests only cover math.
- Shaders (WGSL): shaders.wgsl (opaque + transparent share it), sky.wgsl (procedural sky, sun, clouds), underwater_tint, hud/text overlay, hiz. Reverse-Z depth (clear 0.0). Texture: `texture_2d_array` + one sampler (materials.rs builds from PNGs, 128 layer max), generated mipmaps? (not verified; sample uses `fract(uv)` on a repeating greedy quad which is incompatible with naive mip/trilinear derivatives at seams — fract() on uv introduces derivative discontinuities, so mip/aniso artefacts at tile edges). Biome tint via per-face packed RGB + 3 tint modes. 6 debug view modes (face dir, chunk id, draw id, flat white, wireframe).
- LOD: none. Fixed cuboid view radius (12 chunks = 384 blocks horizontally, 4 vertically). No distant terrain, no fog (sky only), no instanced far rendering.
- No MSAA, no post-processing, no shadows, no lighting, no SSAO.

## 7. Bottlenecks and design flaws (ranked)
1. Voxel storage `u32` x 32768 (128 KiB) with no palette / air-chunk elision: 5625 chunks => 720 MB+ resident at default radius; cache-hostile meshing (4x memory traffic); no uniform-chunk fast paths.
2. Main-thread world logic every frame: `streamer.pump` rebuilds `chunk_coords_in_render_radius` (5625-element Vec + sort by a 5-tuple key with a normalize() per element, streaming.rs:215-241) and clones it into a fresh AHashSet (streaming.rs:49-51), then `prune_unwanted` builds a difference set and scans ALL loaded chunks (`world.chunks.keys().filter`, streaming.rs:~100) — O(5625) hash ops + sort per frame even when the player is stationary. `enqueue_dirty` collects + sorts all deferred dirty chunks each frame (meshing.rs:~150-160).
3. Meshing/upload orchestration on the main thread: snapshot capture (7 hash lookups + Arc clones), `mesh_caches` clone for partial rebuilds (`self.mesh_caches.get(&coord).cloned()` — deep clones 384 Vecs on the main thread for every edit, meshing.rs:~160), result receipt (`accept_result` inserts the whole ChunkMeshSlices into a hashmap), 12 `queue.write_buffer` calls per chunk, free-list ops. Upload budget 6 chunks/frame throttles world fill (commit "Slowed down chunk generation for performance" is a symptom: they throttled instead of fixing the cost).
4. Generation is a double bottleneck: 5 ms/chunk x 5625 = 28 CPU-seconds; column noise recomputed for each of 9 Y layers; 3D noise evaluated everywhere; no heightmap early-out (full-air/full-solid chunk classification) — and gets streamed with generation_budget=16/frame.
5. Neighbour-driven double meshing: chunks mesh as soon as generated with absent neighbours as AIR, then re-mesh when neighbours arrive (insert_chunk + mark_adjacent_chunk_borders_dirty).
6. Per-frame CPU rendering overhead scales with chunk count: iterate all entries, up to 12 draws/chunk, sort, HashSet insert, full draw-meta + indirect re-upload, all dirs drawn regardless of facing; draw cap silently truncates. Sorting opaque draws is unnecessary. Mesh pool alloc is linear, `live_face_count` is O(entries) whenever the pool is full; repack is a synchronous copy-all + bind group rebuild (hitches).
7. Greedy mesher is scalar and per-voxel resolved; `Instant::now()` pairs in the inner slice loop; 384 Vec allocations per chunk (+ growth), flatten reallocs.
8. Hi-Z design is a CPU-readback occlusion test — the wrong architecture (latency, device.poll every frame, CPU cost per chunk). Should be GPU compute culling (two-phase Hi-Z or compute frustum cull + MDI/ DrawIndirectCount) — not implemented, disabled.
9. Visual/feature gaps relative to project goals (CLAUDE.md of Lemon wants shadow cascades, SSAO, volumetric): none exist — no lighting, no AO, no depth pre-pass, no fog, no LOD, no transparency OIT beyond sort.
10. Process: no measurement discipline — benchmark exists but no recorded numbers; features (biomes 585 lines, rivers, HUD, 214 Kenney PNGs) took the last 3 days while render perf stayed at CPU-driven draw lists. wgpu 0.20 / winit 0.29 are two major versions behind.

## 8. Port / discard
Worth keeping (ideas, small amounts of code):
- 8-byte packed greedy quad + storage-buffer vertex pulling + unit quad (gpu_types.rs PackedFace; shaders.wgsl vs_main). Good baseline; improve with a per-chunk 32-bit-ish header, AO bits (4x2 bits in tint word), normal/dir from chunk-draw metadata, and non-merged tint (move biome tint to a per-chunk/column texture or sample in FS).
- Per-direction slice buckets (draw only camera-facing dirs) — keep the buckets but add GPU-side culling by direction.
- ChunkMeshDirtyRegion slice-mask idea (mesher.rs:24-130) for cheap incremental edit remesh (maybe not needed if binary meshing is ~100 us/chunk).
- Arc COW chunk snapshots for lock-free meshing; request-id/generation stale-result rejection (generation.rs, meshing.rs accept_result) and the lifecycle monotonicity test cases (lifecycle.rs tests).
- Priority ordering by distance + forward bias (meshing.rs chunk_priority_key) — but compute once per player-chunk change, not per frame.
- Block registry/ResolvedBlock flags (world/block/*), texture-array material builder (materials.rs), TOML config scaffolding (config.rs), async atomic saver with backup/corruption handling (persistence.rs 824 lines — pattern is solid, replace TOML edit log with binary/region format), spawn-finder, player physics (player/physics.rs 344 lines AABB collision), sky.wgsl procedural sky, F3 overlay/text renderer, CI workflow and test suite structure, benchmark scaffolding idea (but make it headless and write numbers to a file).
- MULTI_DRAW_INDIRECT with INDIRECT_FIRST_INSTANCE feature gating + fallback path pattern.
- StagedGenerator structure (column prepare -> solid mask -> material pass) as the reference for correctness; the biome TOML tables/ColumnSample design.

Discard / rewrite:
- u32 Voxel and unpaletted 32^3 flat chunks; AHashMap world as the only index (use flat/ring-buffer chunk grid for the loaded window + palette storage with uniform-chunk fast path).
- Main-thread streaming (full-radius coord Vec/Set rebuild each frame), main-thread mesh_caches/snapshot clones, per-slice write_buffer uploads; replace with staging/ring uploads from worker threads where possible and incremental ring-based load/unload.
- CPU frustum/draw-list build + sorting every frame and all of hiz.rs CPU readback culling -> compute-shader frustum + Hi-Z culling writing indirect args (GPU-driven), per-chunk (not per slice) metadata SSBO, persistent big buffer with a proper allocator (TLSF / buddy, not linear first-fit) and incremental defrag.
- wgpu 0.20/winit 0.29 (move to current), fract()-based UV tiling with mip issues, TOML pretty-printed edit log, the Windows debug.bat flow, the 214-file Kenney asset import (keep only blocks actually used).
- Scalar per-voxel greedy mesher -> binary greedy mesher (u64/u32 column bitmasks, ~100 us/chunk target); scalar f32 Perlin per-voxel generator -> column-cached, SIMD (glam/ wide), coarse-to-fine 3D noise sampling (sample 3D density at 4x4x4 and trilinear interpolate; skip chunks fully above/below surface using heightmap bounds).

## Bottom line
Decaf is a competent feature-demo (generation, biomes, persistence, edit, HUD) wrapped around an architecture whose hot paths are all CPU-driven and main-thread-coupled: ~1.2 ms/chunk meshing, ~5 ms/chunk generation, 128 KiB/chunk voxels, per-frame O(N chunks) streaming + culling + draw-list rebuild. It never got to the GPU-driven pipeline implied by its own DrawMeta/indirect design, and never recorded a measured number. The packed 8-byte quad format and the stale-job/COW-snapshot patterns are the reusable parts; the data layout, streaming loop, and culling should be redesigned from scratch.
