## 2. Architecture
- `src/engine/{core(app.rs 347, mesher.rs 637), render(~20 files), config.rs 918}`, `src/game/{world(manager 702, generator 2043 + generator/{flora 526, pyramid 536}, chunk, blocks, raycast, streamer 62), math, physics, input}`. Engine depends on game (config.rs imports `game::world::generator::pyramid::DETAIL_LEVEL_COUNT`, mesher imports game Chunk) -> layering is nominal. `streamer.rs` seems dead-ish.
- Flow: ChunkManager.update (manager.rs:353) -> rebuild_load_window on chunk-cell crossing -> pending_scratch (sorted far->near, pop nearest) -> dispatch_pending (465) `rayon::spawn` { generate_chunk; if non-empty: boundary_planes + mesh_chunk } -> mpsc channel -> main thread apply_completed_generations (592): `alloc_chunk` + `queue.write_buffer` per direction + `update_chunk_meta` write -> GPU cull compute -> multi_draw_indirect_count x6.
- Threading: global rayon pool (all cores, so workers compete with the main thread; fixed only by an in-flight cap of 2x threads, manager.rs:128). Main thread never blocks on joins; GPU timer & stats use map_async + `device.poll(Poll)`. Main thread DOES do per-frame budgeted uploads (`write_buffer` of mesh data, memcpy) and drains with max_chunk_{dispatches,uploads,unloads}_per_frame budgets (frame-budget hacks, config.rs). No dedicated meshing pool, no priority/cancellation of in-flight jobs (stale jobs are generated then discarded if out of window, manager.rs:594).
- Edit path (set_block, 259) is synchronous on main thread: remeshes chunk + up to 6 neighbours inline using `is_solid_at` fallbacks; edits are not stored anywhere but the pool chunk -> lost on unload (no persistence), and regenerating chunk re-derives from noise.

## 3. Data structures
- `Chunk { blocks: [u16; 32768] }` (chunk.rs:7) = 64 KiB flat, index x + y<<5 + z<<10. NO palette/bit-packing, no uniform-chunk (all-air/all-stone) compression, no light, no metadata.
- World = `HashMap<(i32,i32,i32), LoadedChunk>` with custom multiplicative hasher (manager.rs:32, `CoordMap`). Chunk memory lives in `pool: Vec<Option<Box<Chunk>>>` + free list, preallocated at start: pool size is forced up to load volume (render_distance 32, vert 4 => 38k chunks => 2.4 GB RAM, cap 65536 = 4 GiB, config normalized()). Even air chunks keep a 64 KiB slot (is_empty kept in LoadedChunk but slot not freed). This is the biggest scalability flaw: RAM-bound render distance; the "infinite distance" claim in e97f5c9 is "bounded by RAM".
- Boxed-chunk trick (631d477) avoids 64 KiB memcpy x4 -- fine, but symptomatic of storing fat arrays in channels.
- GPU: pool_slot index doubles as chunk_meta index (cull input) -> nice trick: CPU never builds a visible list.

## 4. Meshing (mesher.rs, 637 lines incl. tests)
- Actual algorithm: HYBRID. "Binary" part = per-axis u32 column bitfields (`build_solidity_columns` 59-72 scalar loop over 32768 voxels, 3 RMW writes each) + exposure via shift/AND-NOT (`compute_exposure`, three near-identical copy-pasted 25-line loops). Then per (dir,layer) the mask is populated by scalar loops of 1024 cells (`populate_mask_from_exposure`, with `get_block` bounds-checked) and merged with classic scalar greedy (`merge_mask_into_faces`, per-id compare) -- NOT the bit-twiddling binary greedy (mikola/cgerikj `trailing_zeros`-run merging). Merge condition: identical u16 id only; no AO -> no AO-split issue, but also no baked AO / light.
- Every nonzero id is "solid & opaque", including WATER (blocks.rs, textures id==block id): water renders as an opaque textured cube, no transparent pass (ARCHITECTURE.md s6 claims one; none exists; no blend state in the chunk pipeline). Block id doubles as texture layer (id & 0x7F) -> max 127 blocks, no per-face textures (grass side/top same layer).
- Output: `DirectionalMesh { faces: [Vec<u32>; 6] }`, face = 1 u32 {x5,y5,z5,tex7,w5,h5} (mesher.rs:63). Width/height max 32 fits. Vertex pulling: instance per face, 6 vertices, no index buffer (vs_main shader.wgsl:56).
- Neighbour handling: the async path passes `[None;6]` and uses procedural prediction of neighbour voxels via `TerrainGenerator::boundary_planes` (generator.rs:1090 + 3 x ~170-line `solid_plane_{x,y,z}` copies). I.e. the mesher is coupled to the world generator. Consequences: (a) boundary_planes is 4-10x the cost of meshing itself, (b) any block edit / tree / non-pure-function feature breaks it, (c) generator must evaluate noise for the 6 neighbour faces => same noise computed ~2x, (d) needed regression tests, many bug commits. Right design: mesh with real neighbour 34^3 padded data once neighbours exist (or 2-phase: gen -> mesh when 6 neighbours ready).
- MEASURED (release, this box, 4 cores shared): terrain_bench: gen surface 297 us, deep 820 us, sky 59 us, tunnel 814 us; gen+mesh surface 1859-1913 us, deep 1516-1556, tunnel 1547. Own split bench (/tmp/.../scratchpad/tb/split.rs): surface chunk (253 faces, 1248 solid voxels): gen 348 us, boundary_planes 1423 us, mesh_chunk with trivial neighbour 155 us. Deep chunk (32588/32768 solid, 307 faces): gen 850, boundary_planes 433, mesh 224. Air chunk: boundary_planes 2442 us (skipped in practice by the is_empty check). mesh_bench (exact is_solid fallback): 6221 us surface / 1238 us solid -> "Ziel <1ms: VERFEHLT" (claimed 643 us in 631d477; claim not reproducible, commit stats were on a different machine and before the later is_solid changes). So pure meshing ~0.15-0.25 ms (OK, non-SIMD), but the end-to-end per-chunk cost is 1.5-1.9 ms, ~5-10 chunks/s/core... actually ~600 chunks/s/core => ~2000/s on 4 cores; the 38k-chunk startup window takes ~20+ s. Commit-claimed 845 chunks/s/thread gen alone (pyramid commit, 1.18 ms/chunk) was with 1 thread.
- Face counts are tiny (~250-300 faces / terrain chunk, ~1 KB), so GPU memory is not the constraint; CPU generation is.
- No quad-level face merging across chunks, no LOD in the mesh, no ambient occlusion / vertex light, no per-face tint.

## 5. Rendering
- Buffers: per-direction ONE persistent `faces_buffer` (3M faces=12 MB each, max_faces_per_direction in config) managed by `SubAllocator` (renderer.rs:38): first-fit free-list Vec<(u32,u32)> with O(n) scan and Vec insert/remove; coalesces on free (in place since 631d477). No defragmentation, no size classes; allocation failure -> chunk part silently dropped with a log::warn (renderer.rs:~474). Fine for tiny meshes, would fragment under edits. Upload = `queue.write_buffer` from main thread per direction per chunk (staging copy each; up to N per frame). Better: one staging belt / persistent mapped ring, batch.
- Culling: `cull.wgsl` one thread per POOL SLOT (all 38k, even inactive: early return on aabb_min.w<0.5), frustum 5 planes + HZB occlusion, atomicAdd compaction per direction into `combined_indirect_buffer`, `multi_draw_indirect_count` x6 (one per direction; renderer.rs:678). Real GPU-driven pipeline, works (headless check passes, render path tested). Weaknesses: (1) SINGLE phase: occlusion test against previous-frame HZB reprojected through the new matrix with no "second pass" to re-test culled chunks -> disocclusion pop-in, so they added a 48-block no-occlusion radius hack (cull.wgsl:25, commit 2930deb) -> NOT the two-phase scheme (draw last-frame-visible, build HZB, test rest). (2) No per-direction back-face culling in cull: all 6 dirs are emitted for every visible chunk (about half of directional meshes are backfacing; only the HW backface cull, applied after vertex shading of 6 verts/instance, removes them). Easy win: skip dirs whose normal faces away from camera relative to the chunk AABB. (3) HZB built via 2 compute passes from the MSAA depth buffer, loops all MSAA samples with min (hzb.rs; R32Float, up to 10 mips). MSAA depth => expensive HZB copy. (4) Instance_count = face count, vertex_count=6 per draw: one draw per chunk-direction => thousands of tiny draws inside multi_draw; fine.
- Pipeline: reverse-Z Depth32Float GreaterEqual (pipeline.rs:239), CCW + back cull. MSAA default config (msaa_samples; SSAO requires MSAA>1 -- "SSAO deaktiviert: benoetigt Multisampled Depth", context.rs:162; weird coupling: SSAO disabled when MSAA off). Opaque pass -> skybox pass -> SSAO pass (raw AO) -> blur pass (bilateral, multiplies) -> HUD. No transparent pass, no TAA/SMAA, godrays disabled (context.rs:~270 commented out; compute godray code still compiled).
- Shadows (shadow.rs:150 `render_cascades`): for each cascade (3-4) one render pass with a CPU-built union list of chunks whose AABB hits ANY cascade sphere (manager.rs:542 `update_shadow_visibility`, dirty-flag cached). So every chunk in the union is redrawn in EVERY cascade (up to 4x geometry cost, no per-cascade culling, no GPU cull for shadows, no caching of static cascades, no texel snapping evidence beyond "swimming" fix). Shadow draw = `multi_draw_indirect` (not count) from CPU buffers re-uploaded when dirty. All 6 directions drawn into shadow maps (no light-facing-direction filter; half are back faces wasted). PCF 3x3 = 9 comparison taps per pixel. Better: per-cascade GPU cull, only 3 sun-facing directions, cache far cascades.
- SSAO (ssao.wgsl): kernel loop of textureLoad on multisampled depth (reads sample 0 only), + bilateral blur; screen space as the CLAUDE.md demands; no normal buffer. 
- gpu_timer.rs: timestamp queries only around the opaque pass (2 slots), uses `Arc<Mutex<bool>>` (renderer.rs's own stats readback was converted to AtomicBool, gpu_timer wasn't). Shadow, cull, HZB, SSAO, blur are NOT timed -> performance claims for the whole frame can't be derived. HUD shows GPU ms of opaque only.
- Present mode = `surface_caps.present_modes[0]` (context.rs:129), i.e. whatever the driver lists first (usually Fifo/vsync), so reported "500-750 FPS" must have been Immediate/AutoNoVsync or uncapped by luck - unclear.
- Textures: 16x16 procedural layers in a Texture2DArray (9 layers). No atlas bleeding issue; greedy UV repeat uses sampler repeat; mipmaps absent in what I saw (textures.rs).

## 6. World generation
- generator.rs 2043 lines: `generate_chunk` alone = lines 1250-1560 (310-line god function); `solid_plane_x/y/z` 593-1090 (~500 lines, three near-duplicates). Plus 4 thread_local caches with hand-rolled hash slots (COLUMN_CACHE 4096, HEIGHT_CACHE, cave grid caches), config.rs-driven magic.
- Noise: `noiz` 0.5 + `bevy_math` 0.19 Vec2/Vec3 (pulls bevy_math tree; not glam). Scalar one-point-at-a-time `noise.sample(point)` (generator.rs:289-327; ~200 ns/sample for 4 octaves per their comments, 280 ns for Worley). No batching/SIMD: the "SIMD-accelerated" commit title (05b7765) is untrue: only sparse grid + trilinear interpolation tricks, later (2930deb) ripped out for exactness (caves now exact, which is why deep chunks cost 0.8 ms). `noiz` does expose SIMD-able primitives but the code evaluates per voxel column / per grid corner.
- Terrain: TerrainPyramid (pyramid.rs 536 lines): hierarchical window blend ("MultiDiffusion"), windows memoized in RwLock<HashMap<..., Arc<WindowData>>> (global lock contention across rayon workers), thermal erosion per window. Design is sound (deterministic in world coords, order-independent) but heavy. Caves: two Worley tunnel systems + cheese caves, with Slab-extremity bounds. Trees: deterministic cross-chunk radius sampling with space colonization (flora.rs) -- no need for neighbouring chunk data, which is a good property but each chunk re-simulates every nearby tree.
- Cost (measured): sky 59 us, surface 297-350 us, deep/tunnel 820-850 us per chunk = ~25 ns/voxel deep. For a 38k-chunk window gen alone = ~13-30 s of single-core CPU. They themselves measured 1.18 ms/chunk when pyramid landed.
- Terrain cost story: the budget kept being exceeded (2 ms goal), each fix added a cache -> complexity (HEIGHT_CACHE, COLUMN_CACHE, boundary_planes, cave grid, slab bounds). Time spent on terrain realism (≈25 of 50 commits) overshadowed rendering perf work.

## 7. Bottlenecks / design flaws / smells
1. Mesher<->generator coupling for borders (boundary_planes 1.4 ms vs mesh 0.15 ms). Single biggest CPU waste and source of correctness bugs (gaps, race with player edits).
2. 64 KiB/chunk fixed u16 arrays + preallocated pool sized to the full load volume -> GBs of RAM, no sparse/palette chunks, air chunks retain slots. Distance is RAM-bound; the LOD attempt was dropped.
3. Raw HashMap lookups + per-frame O(window) logic (rebuild_load_window on cell crossing, shadow visibility full scan with par_iter) -> the O(1) window predicate fix helped but structure is still HashMap of 38k.
4. Main-thread upload path via write_buffer per chunk; frame-budget caps (dispatch/upload/unload per frame) as band-aids; rayon global pool starving main (bf6e836 root cause) -> need a dedicated pool (num_cpus-1 or lower priority) and a work queue with priority + cancellation.
5. Shadows: all cascades redraw union; both fronts and backs; CPU-compacted lists; MSAA + SSAO + HZB all coupled to a multisampled depth.
6. Cull: single-phase, hack radius; draws 6 directions regardless of facing; thread per pool slot.
7. No transparent pass despite water; water is opaque cube; id==texture.
8. config.rs 918 lines: each setting exists in 3 forms (PlayerSettings, DevSettings, *File structs + 4 From impls, 575-918) = pure boilerplate; ~35 terrain knobs; the "no magic numbers" rule in ARCHITECTURE s9 caused this plus giant doc comments. Comments violate CLAUDE.md "no unnecessary comments" everywhere (doc comments of 5-15 lines on nearly every item, in German).
9. Process: ideas tested in debug builds, LOD built in one day then deleted, claims in commit messages not re-verified (mesh_bench "643 us" vs 6.2 ms now; "SIMD"; "<1ms").
10. ARCHITECTURE.md vs reality: Transparent pass (absent), TAA/SMAA (absent), godray radial blur (compute godrays, disabled), floodfill lighting (absent), LOD (removed), "Zero-alloc runtime" (mostly; DirectionalMesh Vecs alloc per chunk on workers; per-chunk Vec<u32>), "chunk GPU buffers preallocated" (yes, per-direction arenas), "texture_id 0..127" (yes), single `draw_indirect` (it is 6x multi_draw_indirect_count -- better than doc).
11. Correctness bugs in history: winding inversion (a210dc9); border gaps from interpolated vs exact height (b6d56e0); HZB reprojection flash in caves (2930deb); config reset on unknown field (deny_unknown_fields); pool-size mismatch writing beyond chunk_meta_buffer (631d477); shadow leak in caves (e6729ab, 24-block magic margin); skybox NDC z=inf; physics stuck-on-ground (d523799). Pattern: bugs cluster where state is duplicated (exact vs approximate world queries).

## 8. Keep / port / discard
KEEP (idea or code):
- Face u32 format (5/5/5/7/5/5) + vertex pulling with `draw_index` -> per-draw chunk origin in a storage buffer, `multi_draw_indirect_count` with GPU-written args/count (renderer.rs, cull.wgsl, shader.wgsl). Confirmed to run on lavapipe and an Intel iGPU. Requires wgpu features MULTI_DRAW_INDIRECT_COUNT, INDIRECT_FIRST_INSTANCE, SHADER_DRAW_INDEX (check how context.rs requests them).
- Pool-slot-as-GPU-index trick; reverse-Z Depth32Float; HZB R32Float min-reduction with MSAA loop (hzb*.wgsl) as starting point (but add two-phase).
- Column-bitfield exposure (`col & !(col>>1)`), any_exposed layer skipping, popcount reserve, thread-local scratch (mesher.rs) -> extend to true binary greedy (trailing_zeros runs, per-voxel-type planes).
- CoordHasher; In-flight backpressure idea; nearest-first pending sort; shadow dirty-skip with slack-inflated spheres; CSM cascade sphere fitting (cascades.rs, 164 lines) - review for texel snapping.
- Async stats readback via map_async + AtomicBool; timestamp queries (extend to all passes).
- Tests that cross-check predicted vs generated borders (idea) - moot if design fixed.
- Deterministic cross-chunk tree footprint idea, pyramid windowed terrain only if terrain quality matters; it's the most expensive part.
DISCARD:
- boundary_planes / solid_plane_{x,y,z} / is_solid prediction / HEIGHT_CACHE / COLUMN_CACHE (replace by mesh-after-neighbours or padded 34^3 voxel input).
- Fixed 64 KiB pool; HashMap<Box<Chunk>> sized for full window.
- config.rs triple-struct boilerplate (use a single serde struct with defaults).
- Per-cascade union redraw, CPU shadow lists; draw-all-6-directions; 48-block occlusion hack.
- bevy_math dependency; terrain knob explosion; ring LOD code (already deleted).
- SubAllocator first-fit Vec (fine at this scale; replace with size-class/TLSF or fixed slab since meshes are tiny: ~250 faces).

## 9. Recommendations for the next engine (perf-first)
1. Make mesh input self-contained: padded 34^3 (or 3x3x3 neighbor Arc) data; generate -> mark ready; mesh when 6 face neighbours are present (or mesh immediately with border from lower-LOD/placeholder and remesh on neighbour arrival, cheap at 0.15 ms).
2. Palette/uniform-compressed chunk storage (air/solid single value, 4/8/16-bit palettes); keep 32^3.
3. True binary greedy meshing per block type with u64 or u32 runs; target <50 us/chunk.
4. Dedicated mesh/gen thread pool, priority queue by distance, cancellation; main thread does only staging-belt uploads.
5. GPU: two-phase HZB occlusion, per-direction backface cull in cull shader, per-cascade GPU cull for shadows with only light-facing directions, cache far cascades, time EVERY pass with timestamps, offer present_mode Immediate for benchmarking.
6. Add a headless lavapipe benchmark harness (works here) + CI; record real numbers in commits; measure in release only.
7. Terrain: batch noise (SIMD, 4-8 columns at a time, e.g. `noise` crates with f32x8 / own Simplex/value noise on `wide`/`std::simd`), 2D heightmap per column once per column-stack, 3D cave noise at stride 4 with exact border not needed if meshing uses real neighbour data (the interpolation was dropped ONLY because of the neighbour-prediction mismatch).
